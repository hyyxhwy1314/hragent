# 流程扩展开发指南（转正 / 调岗 / 离职）

> 本文档基于已实现的「入职流程」样板，指导你无需改动任何现有代码即可扩展另外 3 个流程。
>
> 适用范围：HR Agent 后端 `org.example.hragent`
>
> 前置阅读：[Flowable工作流引擎集成设计文档.md](./Flowable工作流引擎集成设计文档.md)

---

## 一、核心机制：为什么新增流程"零改动"

整个流程引擎通过**策略模式**实现流程类型路由，关键三件套：

```
AssigneeStrategy（策略接口）
        ↑ 实现
OnboardAssigneeStrategy（入职策略）
        ↓ 注入
AssigneeResolverImpl（路由器）
   └─ 启动时扫描所有 AssigneeStrategy Bean
   └─ 按 supportProcessKey() 构建 key→策略 映射
   └─ 发起流程时按 processKey 路由到对应策略
```

**结论**：新增流程 = 新增 1 个 BPMN 文件 + 1 个策略 Bean + 常量。`AssigneeResolverImpl` 通过 Spring 自动注入新 Bean，**无需改动它，也无需改动 Controller / Service / Orchestrator**。

## 二、实现一个新流程的标准 3 步

### 第 1 步：写 BPMN 流程定义

文件位置：`src/main/resources/processes/{flowKey}.bpmn20.xml`

- `<process id>` 必须与策略的 `supportProcessKey()` 完全一致
- 审批人用表达式 `${approver_xxx}`，变量名由策略返回
- 网关条件用 `${approved}` / `${!approved}`，由 `completeTask` 写入
- 需要分支时用业务变量（如 `${probationMonths >= 6}`），由策略或 `bizJson` 写入

### 第 2 步：写审批人策略

文件位置：`src/main/java/org/example/hragent/service/impl/{Flow}AssigneeStrategy.java`

实现 `AssigneeStrategy` 接口，两个方法：

```java
@Component
public class XxxAssigneeStrategy implements AssigneeStrategy {

    private final EmployeeMapper employeeMapper;

    public XxxAssigneeStrategy(EmployeeMapper employeeMapper) {
        this.employeeMapper = employeeMapper;
    }

    @Override
    public String supportProcessKey() {
        return "xxx-process";  // 与 BPMN 的 process id 一致
    }

    @Override
    public Map<String, String> resolve(Long bizId, Long applyEmpId) {
        // 查审批人，返回变量映射
        // key 必须与 BPMN 中的 ${approver_xxx} 对应
        // value 是审批人员工ID的字符串
        // 找不到审批人抛 BusinessException(ErrorCode.FLOW_APPROVER_NOT_FOUND, "说明")
    }
}
```

### 第 3 步：加常量（可选）

在 `FlowConstants.java` 中：

```java
public static final String PROC_KEY_XXX = "xxx-process";
public static final String FLOW_TYPE_XXX = "XXX";
```

`flowTypeOf()` 的 switch 分支会自动映射。不加也行——会回退 `processKey.toUpperCase()`，但建议加，便于统一管理。

### 完成后

- **重启后端**：引擎启动时自动部署 `processes/` 下所有 BPMN，自动注入新策略 Bean
- **前端**：在 `flow/index.vue` 的「发起流程」下拉选项里加一项即可

## 三、转正流程（regular-process）

### 业务规则

| 节点 | 审批人 | 说明 |
|---|---|---|
| 主管评估 | 申请人直属上级（`leader_id`） | 第一审批人 |
| 网关：试用期 ≥ 6 个月？ | — | 条件分支 |
| ├ 是 | HR 复核 | 长试用期需 HR 二次确认 |
| └ 否 | 直接到结束 | 短试用期主管通过即可 |
| 结束 | — | 转正完成 / 转正驳回 |

### 涉及的流程变量

| 变量名 | 来源 | 用途 |
|---|---|---|
| `approver_dept_leader` | 策略返回 | 主管节点 assignee |
| `approver_hr` | 策略返回 | HR 复核节点 assignee |
| `probationMonths` | 策略返回 | 网关条件 `${probationMonths >= 6}` |
| `approved` | completeTask 写入 | 网关判断通过/拒绝 |

### BPMN 文件 `processes/regular.bpmn20.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<definitions xmlns="http://www.omg.org/spec/BPMN/20100524/MODEL"
             xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
             xmlns:flowable="http://flowable.org/bpmn"
             id="Definitions_regular"
             targetNamespace="http://flowable.org/bpmn">

    <process id="regular-process" name="转正流程" isExecutable="true">

        <startEvent id="regular_start" name="发起转正"/>
        <sequenceFlow id="flow_1" sourceRef="regular_start" targetRef="regular_1_leader_audit"/>

        <!-- 节点1：主管评估 -->
        <userTask id="regular_1_leader_audit" name="主管评估"
                  flowable:assignee="${approver_dept_leader}"/>
        <sequenceFlow id="flow_2" sourceRef="regular_1_leader_audit" targetRef="regular_gw_leader"/>

        <!-- 网关1：主管评估结果 -->
        <exclusiveGateway id="regular_gw_leader" name="主管评估结果"/>
        <sequenceFlow id="flow_3" sourceRef="regular_gw_leader" targetRef="regular_gw_probation">
            <conditionExpression xsi:type="tFormalExpression">${approved}</conditionExpression>
        </sequenceFlow>
        <sequenceFlow id="flow_4" sourceRef="regular_gw_leader" targetRef="regular_end_rejected">
            <conditionExpression xsi:type="tFormalExpression">${!approved}</conditionExpression>
        </sequenceFlow>

        <!-- 网关2：试用期是否≥6个月 -->
        <exclusiveGateway id="regular_gw_probation" name="试用期≥6个月?"/>
        <sequenceFlow id="flow_5" sourceRef="regular_gw_probation" targetRef="regular_2_hr_review">
            <conditionExpression xsi:type="tFormalExpression">${probationMonths >= 6}</conditionExpression>
        </sequenceFlow>
        <sequenceFlow id="flow_6" sourceRef="regular_gw_probation" targetRef="regular_end">
            <conditionExpression xsi:type="tFormalExpression">${probationMonths &lt; 6}</conditionExpression>
        </sequenceFlow>

        <!-- 节点2：HR 复核 -->
        <userTask id="regular_2_hr_review" name="HR复核"
                  flowable:assignee="${approver_hr}"/>
        <sequenceFlow id="flow_7" sourceRef="regular_2_hr_review" targetRef="regular_gw_hr"/>

        <!-- 网关3：HR复核结果 -->
        <exclusiveGateway id="regular_gw_hr" name="HR复核结果"/>
        <sequenceFlow id="flow_8" sourceRef="regular_gw_hr" targetRef="regular_end">
            <conditionExpression xsi:type="tFormalExpression">${approved}</conditionExpression>
        </sequenceFlow>
        <sequenceFlow id="flow_9" sourceRef="regular_gw_hr" targetRef="regular_end_rejected">
            <conditionExpression xsi:type="tFormalExpression">${!approved}</conditionExpression>
        </sequenceFlow>

        <endEvent id="regular_end" name="转正完成"/>
        <endEvent id="regular_end_rejected" name="转正驳回"/>
    </process>
</definitions>
```

> 注意：XML 中 `<` 必须写成 `&lt;`，否则解析失败。

### 策略 `RegularAssigneeStrategy.java`

```java
package org.example.hragent.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import lombok.extern.slf4j.Slf4j;
import org.example.hragent.entity.Employee;
import org.example.hragent.exception.BusinessException;
import org.example.hragent.exception.ErrorCode;
import org.example.hragent.mapper.EmployeeMapper;
import org.example.hragent.service.AssigneeStrategy;
import org.springframework.stereotype.Component;

import java.time.LocalDate;
import java.time.Period;
import java.util.HashMap;
import java.util.Map;

@Slf4j
@Component
public class RegularAssigneeStrategy implements AssigneeStrategy {

    private final EmployeeMapper employeeMapper;

    public RegularAssigneeStrategy(EmployeeMapper employeeMapper) {
        this.employeeMapper = employeeMapper;
    }

    @Override
    public String supportProcessKey() {
        return "regular-process";
    }

    @Override
    public Map<String, String> resolve(Long bizId, Long applyEmpId) {
        Map<String, String> result = new HashMap<>();

        Employee applicant = employeeMapper.selectById(applyEmpId);
        BusinessException.throwIf(applicant == null, ErrorCode.EMP_NOT_EXIST);

        // 主管 = 申请人直属上级
        Long leaderId = applicant.getLeaderId();
        BusinessException.throwIf(leaderId == null, ErrorCode.FLOW_APPROVER_NOT_FOUND, "未找到申请人直属上级");
        result.put("approver_dept_leader", String.valueOf(leaderId));

        // HR（复核节点用）
        Employee hr = employeeMapper.selectOne(new LambdaQueryWrapper<Employee>()
                .eq(Employee::getRole, "HR").last("LIMIT 1"));
        BusinessException.throwIf(hr == null, ErrorCode.FLOW_APPROVER_NOT_FOUND, "未找到 HR 角色员工");
        result.put("approver_hr", String.valueOf(hr.getId()));

        // 计算试用期月数（entry_date 至今）
        int probationMonths = 6; // 默认
        if (applicant.getEntryDate() != null) {
            probationMonths = Period.between(applicant.getEntryDate(), LocalDate.now()).getMonths();
        }
        result.put("probationMonths", String.valueOf(probationMonths));

        log.info("转正流程审批人解析 bizId={}, applyEmpId={}, leader={}, hr={}, probationMonths={}",
                bizId, applyEmpId, leaderId, hr.getId(), probationMonths);
        return result;
    }
}
```

### 常量（可选，加到 `FlowConstants.java`）

```java
public static final String PROC_KEY_REGULAR = "regular-process";  // 已存在
public static final String FLOW_TYPE_REGULAR = "REGULAR";          // 已存在
```

`flowTypeOf()` 已有 `regular-process` → `REGULAR` 分支，无需改。

### 测试

```powershell

curl -X POST http://localhost:8080/flow/process/start `
  -H "Content-Type: application/json" `

```

## 四、调岗流程（transfer-process）

### 业务规则

| 节点 | 审批人 | 说明 |
|---|---|---|
| 原主管审批 | 申请人当前 `leader_id` | 第一审批人 |
| 新主管审批 | 目标部门负责人 | 由申请人在 `bizJson` 中指定 |
| 网关：是否跨部门？ | — | 条件分支 |
| ├ 跨部门 | HRBP 审批 | 跨部门需 HRBP 介入 |
| └ 同部门 | 直接结束 | 同部门调岗无需 HRBP |
| 结束 | — | 调岗完成 / 调岗驳回 |

### 涉及的流程变量

| 变量名 | 来源 | 用途 |
|---|---|---|
| `approver_old_leader` | 策略返回 | 原主管节点 assignee |
| `approver_new_leader` | 策略返回 | 新主管节点 assignee |
| `approver_hrbp` | 策略返回 | HRBP 节点 assignee |
| `crossDept` | 策略返回 | 网关条件 `${crossDept == true}` |
| `approved` | completeTask 写入 | 网关判断通过/拒绝 |

### BPMN 文件 `processes/transfer.bpmn20.xml`

### 策略 `TransferAssigneeStrategy.java`

```java
package org.example.hragent.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import lombok.extern.slf4j.Slf4j;
import org.example.hragent.entity.Employee;
import org.example.hragent.exception.BusinessException;
import org.example.hragent.exception.ErrorCode;
import org.example.hragent.mapper.EmployeeMapper;
import org.example.hragent.service.AssigneeStrategy;
import org.springframework.stereotype.Component;

import java.util.HashMap;
import java.util.Map;

@Slf4j
@Component
public class TransferAssigneeStrategy implements AssigneeStrategy {

    private final EmployeeMapper employeeMapper;

    public TransferAssigneeStrategy(EmployeeMapper employeeMapper) {
        this.employeeMapper = employeeMapper;
    }

    @Override
    public String supportProcessKey() {
        return "transfer-process";
    }

    @Override
    public Map<String, String> resolve(Long bizId, Long applyEmpId) {
        Map<String, String> result = new HashMap<>();

        Employee applicant = employeeMapper.selectById(applyEmpId);
        BusinessException.throwIf(applicant == null, ErrorCode.EMP_NOT_EXIST);

        // 原主管 = 申请人当前 leader_id
        Long oldLeaderId = applicant.getLeaderId();
        BusinessException.throwIf(oldLeaderId == null, ErrorCode.FLOW_APPROVER_NOT_FOUND, "未找到原主管");
        result.put("approver_old_leader", String.valueOf(oldLeaderId));

        // 新主管 + 是否跨部门：从 bizJson 读取 targetDeptName / targetLeaderId
        // 简化实现：假设 bizJson 形如 {"targetDeptName":"研发部","targetLeaderId":3}
        // 这里只做演示，实际解析 JSON 用 Jackson
        String targetDeptName = "研发部";   // TODO: 从 bizJson 解析
        Long targetLeaderId = 3L;            // TODO: 从 bizJson 解析
        result.put("approver_new_leader", String.valueOf(targetLeaderId));
        result.put("crossDept", String.valueOf(!targetDeptName.equals(applicant.getDeptName())));

        // HRBP（跨部门时用）
        Employee hrbp = employeeMapper.selectOne(new LambdaQueryWrapper<Employee>()
                .eq(Employee::getRole, "HRBP").last("LIMIT 1"));
        if (hrbp != null) {
            result.put("approver_hrbp", String.valueOf(hrbp.getId()));
        }

        log.info("调岗流程审批人解析 bizId={}, applyEmpId={}, oldLeader={}, newLeader={}, crossDept={}",
                bizId, applyEmpId, oldLeaderId, targetLeaderId, !targetDeptName.equals(applicant.getDeptName()));
        return result;
    }
}
```

> `bizJson` 的解析建议用 `com.fasterxml.jackson.databind.ObjectMapper`，从 `dto.getBizJson()` 读 `targetDeptName` / `targetLeaderId`。策略的 `resolve(bizId, applyEmpId)` 当前签名不含 bizJson，如需读取可在 `AssigneeResolver.resolve` 增加一个 bizJson 参数（改动面很小）。

| 现象 | 排查点 |
|---|---|
| 发起报「流程定义不存在」 | BPMN 没部署：检查 `processes/` 下文件 + 重启；或 `GET /flow/process/definitions` 看不到 |
| 发起报「未找到 XX 角色员工」 | `t_employee` 缺对应 role：`UPDATE t_employee SET role='HR' WHERE id=...` |
| 发起报「未找到申请人直属上级」 | 申请人 `leader_id` 为 NULL：`UPDATE t_employee SET leader_id=X WHERE id=Y` |
| 审批后流程不流转 | `approved` 变量没写入：检查 `completeTask` 是否调 `taskService.complete(taskId, vars)` |
| 流程一直「进行中」不结束 | 最后节点通过后没同步状态：检查 `syncFlowStatus` 是否查到运行实例已删除 |
| 轨迹看不到审批结果 | `t_flow_approval` 没记录：检查 `completeTask` 是否插入；旧流程兜底显示「已处理」 |
| 网关条件报错 | 表达式变量名与策略返回的 key 不一致；或 `<` 没转义为 `&lt;` |
| 启动日志没看到新策略 | 策略 Bean 没被扫描：检查 `@Component` + 包路径在 `@ComponentScan` 范围内 |

启动日志应看到（说明策略已加载）：

```
审批人策略加载完成 strategies=[onboard-process, regular-process, transfer-process, leave-process]
```

## 八、数据准备建议

测试新流程前，确保数据：

```sql
-- 设置 HR
UPDATE t_employee SET role='HR' WHERE emp_no='E001';
-- 设置 HRBP（调岗流程用）
UPDATE t_employee SET role='HRBP' WHERE emp_no='E003';
-- 设置部门负责人
UPDATE t_employee SET role='DEPT_LEADER', leader_id=NULL WHERE emp_no='E003';
-- 普通员工设置直属上级
UPDATE t_employee SET leader_id=3 WHERE emp_no IN ('E002','E004');
```

角色与审批人映射关系：

| 角色 | 用于哪些流程节点 |
|---|---|
| HR | 入职 HR 审核、转正 HR 复核、离职 HR 审批 |
| DEPT_LEADER | 入职部门确认、转正主管评估、离职主管审批 |
| HRBP | 调岗 HRBP 审批（跨部门时） |
| EMPLOYEE | 普通员工，可被发起流程 |
