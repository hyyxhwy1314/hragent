# 员工自助模块实施计划

## Context（背景）

根据 HR Agent 各平台调研，为系统补充「员工自助」业务能力，覆盖三大场景：

1. **请假审批 + 假期余额**：员工发起请假 → 直属上级 → HR 两级审批 → 通过后扣减假期余额并邮件通知
2. **在职/收入证明开具**：员工申请 → 审批 → 通过后生成证明内容并以邮件发送
3. **合同/转正到期提醒**：定时任务扫描即将到期员工，邮件提醒 + 提供查询

设计遵循项目既有模式（MyBatis-Plus 实体/Mapper/Service、Flowable 流程 + AssigneeStrategy 策略 + JavaDelegate 回调、Agent @Tool 工具 + ToolFilter 关键词过滤），不引入新框架，保持轻量。

## 新建文件（均在 src/main/java/org/example/hragent/ 下）

| 类别 | 文件 |
|---|---|
| 实体 | `entity/LeaveRequest`、`entity/LeaveBalance`、`entity/CertificateRequest`、`entity/ExpireReminder` |
| Mapper | `mapper/` 对应 4 个，继承 `BaseMapper`，无 XML |
| Service | `service/` 4 个接口 + `service/impl/` 4 个实现（继承 `BaseServiceImpl`）；`LeaveBalanceServiceImpl` 查询加 `@Cacheable("leaveBalance")`，扣减方法加 `@CacheEvict(allEntries = true)` |
| 审批人策略 | `service/impl/AbstractBizRequestAssigneeStrategy`（新抽象基类：bizId=业务单ID → 查申请员工 → 直属上级 + 首个 HR） + `LeaveRequestAssigneeStrategy`、`CertificateAssigneeStrategy` |
| JavaDelegate | `LeaveRequestApprovedDelegate`（扣余额）、`LeaveRequestEmailDelegate`（请假结果邮件）、`CertificateApprovedDelegate`（证明内容落库）、`CertificateEmailDelegate`（发送证明邮件），均 `@Component` |
| 定时任务 | `schedule/ExpireReminderJob`（`@Component` + `@Scheduled(cron = "0 0 2 * * ?")` 每日扫描） |
| 流程定义 | `resources/processes/leave-request.bpmn20.xml`、`certificate.bpmn20.xml` |

## 修改文件

- `resources/sql/init_schema.sql`：追加 4 张表 DDL；`t_employee` 增 `contract_end_date` 列；种子数据补该列
- `constant/FlowConstants.java`：`PROC_KEY_LEAVE_REQUEST`/`PROC_KEY_CERTIFICATE` + `FLOW_TYPE_` 常量 + `flowTypeOf` 2 分支
- `agent/tools/ToolFilter.java`：新增「自助」分类（关键词：请假、假期、年假、余额、证明、合同、到期、提醒等）+ 5 个新工具的 TOOL_CATEGORIES 映射
- `agent/tools/HrBusinessTools.java`：注入新 Service，新增 5 个 @Tool 方法
- `HrAgentApplication.java`：加 `@EnableScheduling`
- `entity/Employee.java`：增量加 `contract_end_date` 字段

## 关键设计决策

1. **bizId = 请假单ID / 证明申请ID**（非员工ID）：`t_flow_instance.biz_id` 直接关联业务单。新建 `AbstractBizRequestAssigneeStrategy` 解析「业务单 → 员工 → 直属上级 + HR」，不改动现有 `AbstractLeaderHrAssigneeStrategy`（其语义为 bizId=员工ID）
2. **假期余额规则（轻量单池）**：工龄满 1 年 5 天/年，不满按入职月数/12×5 取整；`t_leave_balance` 首次查询/扣减时懒初始化（`total_days` 固化、`used_days` 累加、剩余 = total − used）；无年重置任务、无字典表
3. **邮件不复用 `ApprovalEmailDelegate`**：新建独立 delegate，避免在核心类加 flowType if-else 分支；统一复用 `EmailService.sendSimpleMail`。异步邮件节点 `flowable:async="true"`（项目规范）
4. **合同到期不加表**：`t_employee.contract_end_date` 直接算；转正到期 = `emp_status=2` 且转正日期/预计转正日落在 N 天内。提醒写 `t_expire_reminder`（UNIQUE `emp_id + type + expire_date`）去重，防止重复提醒邮件
5. **BPMN 完全镜像 regular.bpmn20.xml**：start → 直属上级审批(${approver_dept}) → 网关(${approved}) → HR 审批(${approver_hr}) → 网关 → 业务 delegate → 异步邮件 delegate → end；驳回走 ${!approved} → end_rejected。bizJson 平铺业务变量（请假：leaveType/startDate/endDate/leaveDays/reason；证明：certType/purpose）
6. **Agent 工具**（`@Tool`，入参 String，返回 LLM 可读文本）：
   - `applyLeaveRequest`：发起请假（建单 + 发起流程，余额不足仅提示不阻断）
   - `queryLeaveBalance`：查本人假期余额
   - `applyCertificateRequest`：发起证明申请（在职/收入）
   - `queryExpireReminders`：查到期提醒列表
   - `queryMyLeaveRequests`：查本人请假记录（join t_flow_instance 得审批状态）
7. **定时任务**：每日扫描提前 30 天合同到期、提前 7 天转正到期 → 邮件发当事员工 → 插提醒记录去重

## 验证方式

1. **DDL**：对运行中的 Docker MySQL（127.0.0.1:13306，root/Admin@888888）执行增量脚本（新表 + `ALTER TABLE t_employee ADD contract_end_date`）；注意不可直接重跑 `init_schema.sql`（会 DROP 旧表）
2. **流程部署**：2 个 BPMN 放入 `resources/processes/` 后重启应用自动部署
3. **端到端**：登录 EMP002（钱员工，直属张主管 id3，HR 李HR id2）
   - 发起请假 2 天 → 张主管通过 → 李HR 通过 → `queryLeaveBalance` 显示余额减少 → 收到结果邮件
   - 发起收入证明 → 两级审批通过 → 收到证明邮件（内容含员工信息）
   - `UPDATE t_employee SET contract_end_date = CURDATE()+5 WHERE id=...` → 次日触发 job（或手动触发）→ `queryExpireReminders` 命中
4. **回归**：现有入职/离职/转正/调岗流程不受影响（未改动其 BPMN/策略/委托）
