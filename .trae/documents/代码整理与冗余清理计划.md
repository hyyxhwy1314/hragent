# 代码整理与冗余清理计划

## Context（背景）

用户要求对项目做一次"整理"：检查代码的统一性与对齐性，删除冗余逻辑，**核心约束是绝不能影响业务功能**。

审计结论（已完成只读排查）：
- 后端整体已相当统一：统一响应体 `R<T>`、统一错误码 `ErrorCode`、统一全局异常 `GlobalExceptionHandler`、CRUD 基建（`BaseController`/`BaseCrudController`/`Converter` 体系）各模块均已对齐使用、缓存注解均在 Service 层且格式统一。
- 真正可安全清理的冗余集中在 3 处：两个"调试/验收"用途的 Controller（用户已确认删除）、一个前端死视图、13 个文件的高置信度未使用 import。
- 工作区有大量未提交的新模块代码（agent/mcp、agent/task、self-service、flow、schedule 等），**一律不碰**。

## 清理项

### 1. 删除后端调试 Controller（用户已确认"两个都删"）

- `src/main/java/org/example/hragent/controller/RedisTestController.java`（`/redis/**`，Redis/分布式锁/限流/防重复提交验收接口）
  - 已核实：其使用的 `@DistributedLock`/`@RateLimit`/`@RepeatSubmit` 三个注解在 ContractReviewController、FlowProcessController、ResumeController、AgentController 中仍在业务使用，删除后切面不会变成死代码。
- `src/main/java/org/example/hragent/controller/DebugMailController.java`（`/debug/mail-test`，注释标注"临时"的 SMTP 验证接口，且存在重复 import `java.util.Map`）
  - 依赖的 `EmailService` 是业务核心服务，保留。

### 2. 删除前端死视图

- `frontend/src/views/aiDashboard/index.vue`
  - 已核实：`router/index.ts` 无对应路由，无任何组件/页面引用它；其功能（AI 概览）已被 `views/dashboard/index.vue` 覆盖。
  - 保留 `frontend/src/api/modules/aiDashboard.ts`（`dashboard/index.vue` 仍在使用 `getSummary`）。

## 明确不做（保护业务，避免过度工程）

- 不合并多套 Resume 服务（ResumeParserService / ResumeAiAnalysisService / ResumeDeepAnalysisService 均在业务链路中使用）。
- 不改动 `R` / `ErrorCode` / `GlobalExceptionHandler` / 各 CRUD Controller / Converter / 缓存注解体系 —— 已统一，重构风险大于收益。
- 不碰未提交的新模块（agent/mcp、agent/task、self-service、flow、schedule、BehaviorLog、annotation/LogAction 等）。
- 不动 `init_schema.sql` / `employee_self_service_ddl.sql` / bpmn 流程文件。
- 根目录杂项文件（img.png、*.ps1、inject-cursor-zh.js、空文件 git、*.log）—— 按用户答复"全部保留"，本次不处理。

## 验证方式

1. 后端：删除与 import 清理后执行 `mvn -q -DskipTests compile`，确认编译通过。
2. 前端：删除视图后 grep 确认无任何文件引用 `views/aiDashboard` 或 `aiDashboard/index`（已在计划前核实，执行时复查一遍）。
3. 改动均为纯删除，无业务逻辑变更；确认 `git status` 中仅出现预期文件的删除/修改。
